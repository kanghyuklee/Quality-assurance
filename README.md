## 설계 원칙

- **요구사항 추적**: 명세가 없는 공개 서비스는 공개 정책에서 요구사항을 역도출하고 출처를 남긴다. 모든 케이스는 요구사항 ID 또는 설계 근거(리스크 기반·추가 검증)로 추적된다.
- **질의사항 분리**: 명세·정책만으로 확정할 수 없는 동작은 질의사항으로 분리하고, 회신 전 처리 원칙("현재 동작 기록 후 판정")을 정한다.
- **설계 기법 명시**: 결정 테이블, 경계값 분석, 상태 전이, 동등 분할, 페어와이즈, 오류 추정 중 무엇을 어디에 썼는지 "규칙의 형태 → 기법" 표로 계획서에 적는다.
- **우선순위와 실행 비용**: P1~P3와 실행 구분(비결제·실결제·장기 등)을 태깅해 실행 계획이 바로 도출되게 한다.
