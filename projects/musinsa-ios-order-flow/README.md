# musinsa-ios-order-flow — 무신사 iOS 앱 주문 플로우 테스트 설계

QA 포트폴리오 프로젝트. 실제 공개 서비스(무신사 iOS 앱)의 주문 플로우를 대상으로 **테스트 계획 수립과 테스트 케이스 설계**를 수행한 산출물이다. 요구사항은 무신사 공개 정책(고객센터 FAQ·이용 안내)에서 역도출했고, 테스트 실행은 범위에 포함하지 않는다.

## 구성

| 파일/폴더 | 내용 |
|---|---|
| `무신사_iOS_주문플로우_테스트계획서.md` | 테스트 계획서. 요구사항(공개 정책 역도출) 추적 매트릭스, 질의사항, 전략·설계 기법, 실행 계획 |
| `무신사_iOS_주문플로우_테스트케이스.xlsx` | 테스트 케이스 90건 + 자동 집계. 시트: 요약 · 테스트케이스 · 테스트 데이터 · 질의사항 · 모바일 체크리스트 · 결함 리포트 |
| `tools/tc_data.py` | 요구사항·질의사항·TC·테스트 데이터·체크리스트의 원본 데이터 |
| `tools/build_xlsx.py` | `tc_data.py`로 케이스 xlsx 생성 |
| `tools/build_md.py` | `tc_data.py`로 계획서 md 생성(요구사항↔TC 매핑·건수 자동 반영) |

## 산출물 재생성

TC를 추가·수정할 때는 `tools/tc_data.py`를 고친 뒤 아래를 실행한다. 계획서의 매트릭스·건수와 케이스 파일이 함께 갱신된다.

```bash
cd tools && python3 build_xlsx.py "../무신사_iOS_주문플로우_테스트케이스.xlsx" && python3 build_md.py "../무신사_iOS_주문플로우_테스트계획서.md"
```

필요 패키지: `openpyxl`

## 설계 요약

- 요구사항 15건(REQ-01~15): 공개 정책에서 역도출, 출처 표기
- 질의사항 12건(Q01~Q12): 정책만으로 확정 불가한 동작 → '현재 동작 기록 후 판정'
- 테스트 케이스 90건: 10개 대분류, P1 30 / P2 37 / P3 23, 설계 근거(요구사항·리스크 기반·추가 검증) 태깅
- 설계 기법: 결정 테이블(적립금 사용 판정), 경계값(5,000원·7%·10원 단위·쿠폰 조건·결제 한도), 상태 전이(주문·결제 상태), 동등 분할(결제수단), 오류 추정
- 모바일 체크리스트 10개 관점 → TC 연결
- 자동화 전략: 케이스별 자동화 구분(API / UI / 수동) 태깅과 계층별 설계(데이터 주도 금액 테스트, Appium UI 스모크, 수동 유지 영역, CI 운영) — 계획서 8장
- 공개 정책 조회일: 2026-10-25
